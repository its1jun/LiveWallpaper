# LiveWallpaper (Windows)

MP4 등의 영상을 Windows 바탕화면 뒤에서 재생하는 저부하 라이브 배경화면 프로그램입니다. 영상 재생에는 **libmpv**를 사용하며, GPU 하드웨어 디코딩을 지원합니다.

## 주요 기능

- 영상을 바탕화면 배경으로 재생
- GPU 하드웨어 디코딩을 통한 저부하 재생
- 화면이 가려지거나 모니터가 꺼지면 재생 일시정지
- (옵션) 오래 가려져 있으면 Windows 바탕화면을 영상 첫 프레임으로 바꾸고 mpv를 완전히 종료
- GIF 및 큰 영상을 모니터 해상도에 맞춰 MP4로 변환
- 시스템 트레이에서 설정 창 열기 및 프로그램 관리
- 중복 실행을 방지하고, 재실행 시 기존 설정 창 표시

## 프로젝트 구조

```text
LiveWallpaper/

├─ README.md
├─ requirements.txt
├─ libs/                libmpv DLL 위치
├─ builder/             빌드 및 배포 파일
│  ├─ build.bat         PyInstaller 및 Inno Setup 실행
│  └─ installer.iss     Inno Setup 스크립트
└─ src/
   ├─ wallpaper.py      바탕화면 부착 및 가림 상태 처리
   ├─ player.py         libmpv 영상 재생기
   ├─ media.py          GIF 변환, 영상 축소, 프레임 제한, 코덱(H.264/H.265) 인코딩, 첫 프레임 추출
   ├─ snapshot.py       Windows 원래 바탕화면 저장·교체·복원 (상태 파일 기반)
   ├─ winapi.py         Windows API, 트레이, 전원 상태, 단일 실행 잠금
   ├─ instance.py       Named Pipe 기반 인스턴스 간 통신
   └─ config.py         JSON 설정 관리
```

## 실행 환경 준비

### 1. Python 패키지 설치

```bash
pip install -r requirements.txt
```

### 2. libmpv DLL 준비

프로젝트의 `libs/` 폴더에 다음 중 하나의 DLL을 넣으세요.

- `libmpv-2.dll`
- `mpv-2.dll`

DLL은 mpv Windows 빌드의 libmpv 개발용 아카이브에서 구할 수 있습니다. 자세한 내용은 [mpv 설치 안내](https://mpv.io/installation/)를 참고하세요. 배포판에 따라 DLL 파일명이 다를 수 있습니다.

EXE로 실행할 때는 EXE와 함께 배포되는 `libs/` 폴더에 DLL이 있어야 합니다.

## 프로그램 실행

설정 창을 표시하며 실행합니다.

```bash
python main.py
```

마지막 영상을 복원하고 트레이에서 시작합니다.

```bash
python main.py --tray
```

### 중복 실행 및 창 다시 열기

프로그램이 트레이에서 실행 중일 때 EXE 또는 `main.py`를 다시 실행하면 새 인스턴스를 만들지 않고 기존 프로그램의 설정 창을 표시합니다.

이 기능은 다음과 같이 구성되어 있습니다.

1. **Win32 Named Mutex**가 단일 실행 여부를 관리합니다.
2. **Windows Named Pipe**가 기존 인스턴스에 `SHOW` 명령을 전달합니다.
3. IPC 서버는 UI 스레드와 분리된 전용 스레드에서 요청을 받습니다.
4. 요청은 thread-safe queue를 통해 Tk 메인 스레드로 전달되며, Tk 메인 스레드가 설정 창을 표시합니다.

이 구조에서는 IPC가 Tk 창 핸들이나 Win32 메시지 루프에 직접 의존하지 않습니다. 요청 전달에 실패하더라도 기존 프로세스를 강제로 종료하지 않습니다.

부팅 시 자동 실행되는 `--tray` 모드는 이미 다른 인스턴스가 실행 중이면 조용히 종료합니다. 이전 버전에서 업데이트한 직후에는 기존 프로세스를 한 번 종료한 다음 새 버전을 실행하세요.

### 사용자 데이터 위치

모든 데이터는 `%APPDATA%`가 아니라 **프로그램 폴더**(개발 중에는 프로젝트 루트, EXE로 실행하면 EXE가 있는 폴더) 안에 저장됩니다.

데이터 경로

---

설정 `<프로그램 폴더>\config.json` 재생용 영상 사본 `<프로그램 폴더>\cache\` 정적 전환 복원 정보 `<프로그램 폴더>\wallpaper_state.json` (정적 전환 중에만 존재)

선택한 영상은 항상 `cache\`에 사본(또는 변환본)을 만들어 재생합니다. 그래서 원본 파일을 지우거나 옮겨도 배경화면이 유지되고 재시작 후에도 복원됩니다. 원본이 남아 있으면 실행할 때마다 변경 여부를 확인하며, 현재 쓰지 않는 사본은 자동으로 정리됩니다. 사본은 영상 용량만큼 디스크를 사용합니다.

## 빌드 및 배포

`builder\build.bat`을 실행하면 다음 작업을 진행합니다.

1. PyInstaller로 실행 파일을 빌드합니다.
2. `builder\dist\LiveWallpaper\` 폴더를 생성하고 필요한 `libs` 파일을 포함합니다.
3. Inno Setup 6이 설치되어 있으면 `builder\output\LiveWallpaper-Setup.exe` 설치 파일도 생성합니다.

### 빌드 환경

- Python 3.10 이상
- 프로젝트 `libs\` 폴더의 libmpv DLL
- 설치 파일을 만들 경우 Inno Setup 6.3 이상

설치 대상 PC에는 별도의 Python 설치가 필요하지 않습니다. 설치는 사용자 단위로 진행되며 관리자 권한을 요구하지 않도록 구성되어 있습니다.

## 저부하 재생 설계

- **하드웨어 디코딩:** `hwdec=auto-safe`를 사용합니다. Windows에서는 D3D11VA가 선택될 수 있으며, 디코딩된 프레임이 GPU 텍스처에 유지되도록 합니다.
- **재생 설정:** 오디오를 비활성화하고 읽기 버퍼를 4MiB로 제한합니다. `profile=fast`를 사용하며 사용자 mpv 설정, 스크립트, yt-dlp는 불러오지 않습니다.
- **화면 가림 처리:** 전체 화면 앱, 잠금 화면, 모니터 꺼짐, 배터리 절약 모드 또는 다른 창에 의해 배경화면이 가려지면 재생을 일시정지합니다. mpv 프로세스는 유지하므로 다시 표시될 때 재생을 이어가도록 설계했습니다.
- **가림 상태 확인 주기:** 재생 중에는 1초, 정지 중에는 2초 간격으로 확인합니다.
- **미디어 최적화:** 화면보다 큰 영상과 GIF는 가져올 때 모니터 해상도에 맞춰 MP4로 변환하며, 프레임 속도는 최대 30fps로 제한합니다. 10-bit 영상이나 비트레이트가 지나치게 높은 영상도 8-bit 4:2:0으로 다시 인코딩합니다(트레이 '옵션'에서 끌 수 있음).
- **cache 코덱 선택:** 설정 창의 `Cache codec`에서 **H.264 (AVC)** 또는 **H.265 (HEVC)** 를 고릅니다(기본 H.264). 원본 코덱이 선택과 다르면 ffmpeg로 재인코딩하고, 같으면서 크기·fps·비트레이트가 적당하면 변환 없이 `cache\`에 복사합니다. 변경한 코덱은 다음 영상 선택/적용 때 반영됩니다.

  | 코덱 | 인코더 | CRF | 비트레이트 상한(1080p 기준) |
  | --- | --- | --- | --- |
  | H.264 | libx264 | 22 | 8 Mbps |
  | H.265 | libx265 | 26 | 5 Mbps |

  프리셋은 `medium`이며, 상한은 출력 해상도(픽셀 수)에 비례해 조정되고 (H.264 2.4~~30 Mbps, HEVC 1.5~~18.75 Mbps) 버퍼는 상한의 2배입니다. HEVC 인코더(libx265)가 없는 ffmpeg 빌드에서는 H.264로 대체합니다. 값은 `src/media.py`의 `CODECS`에서 조정할 수 있습니다.
- **미리보기 관리:** 설정 창이 숨겨지면 미리보기용 mpv를 종료합니다. 바탕화면 재생에는 영향을 주지 않습니다.

## 정적 배경 전환 (옵션)

트레이 **Options → Static wallpaper while hidden** 으로 켭니다 (기본 켜짐). `config.json`의 `static_snapshot`, `snapshot_delay_s`(기본 30초)로도 설정할 수 있습니다.

| 상태 | 동작 |
| --- | --- |
| 가려짐 | 먼저 일시정지만 합니다 (기존 동작). |
| 가려진 채 `snapshot_delay_s` 경과 | ① Windows 바탕화면을 영상 첫 프레임 PNG로 교체 → ② 호스트 창 숨김(파괴하지 않음) → ③ mpv 완전 종료 |
| 다시 보임 | 호스트 창은 숨긴 채 mpv를 영상 처음부터 재시작 → 첫 화면 준비 → 호스트 창 표시 → 원래 바탕화면 복원 (3초 안에 준비 신호가 없어도 전환을 마침) |

바탕화면 이미지는 영상의 첫 프레임이므로 영상은 항상 처음부터 재생합니다 (전환이 이어져 보이도록). 첫 프레임은 영상의 색 변환 규칙(BT.601/BT.709)을 mpv와 같게 맞춰 만듭니다. 영상에 규칙이 표시되어 있으면 그대로 따르고, 없으면 mpv처럼 해상도로 정합니다 (HD → BT.709, SD → BT.601). 첫 프레임은 `cache/`의 `<영상>.frame2-<맞춤>-<가로>x<세로>.png`로 저장되며, 이전 버전의 `.frame-` 파일은 cache 정리 때 지워집니다.

원래 바탕화면은 바꾸기 *전에* `wallpaper_state.json`에 저장합니다. Stop, 종료, 영상 교체, 다음 실행 시작 때 복원하며, 지금 바탕화면이 프로그램이 적용한 것일 때만 되돌려 사용자가 중간에 바꾼 설정을 덮어쓰지 않습니다.

제한 사항: 모니터 1개, 단일 정적 이미지 바탕화면만 지원합니다. 슬라이드쇼·단색·원본 파일 없음·모니터 2개 이상이면 자동으로 기존 일시정지 동작을 유지합니다. 프로세스가 강제 종료되면 다음 실행 때까지 첫 프레임 바탕화면이 남습니다.

## 내부 구성

UI는 Python 기본 라이브러리인 **tkinter**를 사용합니다. 시스템 트레이는 `ctypes`와 `Shell_NotifyIcon`으로 구현했으며, 별도의 UI 패키지는 사용하지 않습니다.

mpv는 전달받은 창 핸들(HWND)에 영상을 그립니다. 바탕화면 호스트 창과 모니터 전원 알림 창은 `ctypes`로 만든 Win32 창입니다.

---

파일 역할

---

`main.py` 프로그램 진입점, tkinter 설정 창, 트레이 메뉴

`src/wallpaper.py` 바탕화면 부착 및 화면 가림에 따른 재생 제어

`src/player.py` libmpv 재생기 및 일시정지·재개 처리

`src/media.py` GIF 변환, 큰 영상 축소, 30fps 제한, H.264/H.265 인코딩

`src/winapi.py` Win32 창, 트레이, 가림 상태, 전원·시스템 상태, 자동 시작, 단일 실행 잠금

`src/instance.py` Windows Named Pipe 서버·클라이언트 및 기존 인스턴스에 창 표시 요청

`src/snapshot.py` Windows 원래 바탕화면 저장·교체·복원 (정적 전환)

## Windows 실기기 검증 항목

아래 항목은 Windows 환경에서 실제 실행해 확인해야 합니다. 개발 환경이나 정적 검사만으로 동작을 확정할 수 없습니다.

- mpv 영상이 바탕화면(Progman)의 자식 창 및 layered 창 구성에서 정상적으로 표시되는지
- 바탕화면 부착 방식 A/B와 Windows 11에서의 창 가림 판정이 올바르게 동작하는지
- Explorer 재시작 또는 부팅 직후 바탕화면이 자동으로 다시 적용되는지
- 트레이에서 실행 중인 상태로 EXE를 다시 실행했을 때 기존 설정 창이 정상적으로 앞으로 표시되는지
- 화면에 가려졌다가 다시 표시될 때 영상이 자연스럽게 이어지는지
- 설정 창 크기를 변경했을 때 미리보기용 mpv 창도 함께 크기가 변경되는지
- 트레이 아이콘 표시, 왼쪽 클릭 시 설정 창 열기, 오른쪽 클릭 메뉴 및 하위 메뉴가 정상 동작하는지
- 모니터 꺼짐 알림이 메시지 전용 창을 통해 정상적으로 전달되는지
- 실제로 D3D11VA 하드웨어 디코딩이 사용되는지
- 정적 전환: `SystemParametersInfoW`로 바꾼 바탕화면이 PNG에서 정상 적용되고, 적용 뒤 `SPI_GETDESKWALLPAPER`가 같은 경로를 돌려주는지 (다르면 복원 판단이 어긋날 수 있음)
- 정적 전환: 숨긴 호스트 창 아래에서 mpv를 다시 만든 뒤 `ShowWindow`로 표시하면 영상이 정상 렌더링되는지, 재시작 후 영상이 처음부터 재생되는지, 전환 순간 깜빡임이 없는지
- 정적 전환: 첫 프레임 PNG의 색이 mpv로 재생한 영상의 색과 같은지 (특히 HDR 영상, 색 표시가 없는 영상)
- 정적 전환 중 화면 해상도 변경·잠금 해제·절전 복귀 때 Windows가 바탕화면을 다시 읽어 와 원래 이미지가 잠깐 보이는지
- 빌드 및 설치 스크립트가 Windows 환경에서 정상적으로 실행되는지

하드웨어 디코딩 여부는 작업 관리자의 GPU **Video Decode** 항목이나 mpv의 `hwdec-current` 값으로 확인할 수 있습니다.
